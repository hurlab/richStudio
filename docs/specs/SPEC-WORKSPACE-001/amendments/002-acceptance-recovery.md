## User decisions (program owner, 2026-10-21)

1. **Manual review deferral.** SPEC-WS-002 verification text requires "CLI accessibility checks plus manual keyboard/focus/zoom/contrast/reduced-motion review". For 002 leaf acceptance only, the manual part is met by automated browser evidence plus independent artifact review. Direct human operation of keyboard, focus, 200% zoom, contrast and reduced motion moves to the SPEC-WS-011 release gate as a named, mandatory hold. This waives timing only. It does not claim accessibility is established; automated scanning alone still does not establish accessibility, and 011 cannot release without the human review. 011 planning must read this amendment.
2. **Negative control.** For 002 acceptance, this supersedes the requirement in `002-check-warning-portability.md` (L29) to release one negative-canary alias at the same SHA. The deliberate negative-control rejection required by `002-hosted-browser-binding.md` (L32) is met by the in-run `workspace-negative` job of run 39664812571, which rejected intentionally broken policy, TypeScript and browser assertion inputs. Not observed, and accepted as residual risk: a hosted run on a `-negative-canary` ref or a `negative_assertion` dispatch, which runs browser-only with `WORKSPACE_NEGATIVE_ASSERTION=1` and is expected to end with a failed job conclusion. That path would show that a deliberate browser assertion failure turns the hosted job red.
3. **200% zoom evidence.** The 200% screenshots of run 39664812571 are partial captures: `page.screenshot({ fullPage: true })` under native browser zoom 2 records only the top-left quarter of the 2x-scaled page (`tests/e2e/design-system.spec.ts`, screenshot call in the layout helper). For 002 acceptance, the SPEC-WS-002 screenshot comparison (L84) for the 200% state is met by the measured layout receipts of the same passed tests in both browser projects: device pixel ratio 2, inner width 640, document scroll width 640, all eight action rectangles within the viewport width, all seven keyboard-reachable actions reached and scrolled into view when focused, and the results table scrolling only inside its own labeled region. These receipts do not judge rendered label and heading text or non-colour state cues at 200%; those remain with the human zoom review held for the 011 release gate. The capture defect is recorded as a hold to fix in the next browser-test change; a complete 200% screenshot comparison is not claimed.
